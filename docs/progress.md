- 2026-10-20: wasm size (Cloudflare Pages refuses files over 25 MiB). Release profile (fat LTO, opt-level "s", one codegen unit) took the `*_bg.wasm` from 27.3 to 19.90 MiB. **Web fonts**: the web build now fetches 15 of verSHion's 20 faces instead of compiling them in (19.90 -> 17.09 MiB).
  - Which faces: `src/fonts.rs` declares every face once (`Face`, marked `embed` or `fetch`). Native builds compile all of them in, as before. The wasm compiles in the four Source Serif 4 faces (equaSHion's `extra-fonts` compiles the same files in, and the linker keeps one copy, so they cost nothing) and `assets/fonts/VSSansFallback-Regular.ttf` (57 KiB: Source Sans 3 Regular cut to Latin and renamed, since the OFL reserves "Source" for unmodified fonts; `tools/make_sans_fallback.py`). Everything else (all four Source Sans 3 faces, Source Serif 4 Semibold, Liberation Mono/Sans/Serif, Noto Sans) is fetched.
  - How: index.html copies `assets/fonts/` to `fonts/` (`copy-dir`, licences included) and preloads the fetched files (`rel=preload as=fetch`), so they download alongside the wasm and the wasm's fetch reuses the preload. `src/web.rs` starts the fetches before opening IndexedDB, waits for them (at most 15 s, `FONT_WAIT_MS`), then hands them to `fonts::install_fetched` before the WebRunner and `App::new_from` exist. The loading screen covers the wait.
  - Why before start, not "register when they arrive": the PDF writer's metrics and subsets (`fonts::metrics`, `subset_with`), resvg's font database (`figures::fontdb`) and the egui font set are all built once from the same bytes; swapping a face mid-session could make a PDF's `/Widths` disagree with its embedded font. So the set is fixed once: `install_fetched` only takes effect before anything has read a face, and the first read freezes it.
  - Fallback: a face that fails (HTTP error, timeout, or a static host answering with an HTML page, which does not parse as a font and is dropped) is drawn with a stand-in for the whole session (`Face::stand_in`: sans faces -> Source Sans 3 Regular, and if that failed too the Latin fallback; serif and mono -> the compiled-in Source Serif 4). egui registers the stand-in's bytes under the missing face's name, so every family keeps its order; resvg loads each distinct face once and maps its generic families to whatever family the sans, serif and mono faces actually are. Nothing panics and no text goes blank; the console lists the faces drawn with stand-ins.
  - Tests: `fonts::every_face_is_its_file_in_assets`, `web_stand_ins_are_compiled_in`, `index_html_ships_and_preloads_the_fetched_faces` (index.html and `Face` must agree), `only_real_fonts_are_taken_from_a_fetch`.
